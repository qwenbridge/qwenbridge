# V9 — Developer Platform

## Goal

V9 turns QwenBridge from a server-only AI search system into a developer-consumable platform.

The release introduces a first-party Java SDK, executable usage examples, resilient client behavior, and developer-facing documentation.

## Scope

### Repository structure

- Restructure the repository into a Maven multi-module project.
- Keep the Spring Boot server in `qwenbridge-server`.
- Add the Java SDK in `qwenbridge-java-sdk`.
- Add runnable examples in `examples/java-sdk-example`.

### Java SDK

- Provide a first-party Java 21 SDK.
- Provide a synchronous `analyze` client API.
- Provide an asynchronous `analyzeAsync` client API.
- Support configurable base URL, connect timeout, and request timeout.
- Support request ID propagation through `X-Request-Id`.
- Map successful API responses to SDK response models.
- Map structured API failures to `QwenBridgeApiException`.
- Map transport failures to `QwenBridgeTransportException`.
- Support a local default client configuration.

### Resilience

- Add configurable retry policy support.
- Classify retryable HTTP failures.
- Retry transient HTTP statuses:
  - `408`
  - `429`
  - `500`
  - `502`
  - `503`
  - `504`
- Retry retryable transport failures.
- Use exponential backoff.
- Support retry behavior for both synchronous and asynchronous analyze calls.
- Preserve interrupted-thread state for synchronous interrupted calls.

### Developer experience

- Add runnable synchronous Java SDK example.
- Add runnable asynchronous Java SDK example.
- Add Java SDK README documentation.
- Document installation, configuration, request IDs, retries, exceptions, and examples.
- Add root README links to SDK documentation and examples.

## Non-goals

The following are intentionally outside V9 scope:

- Maven Central publication.
- Gradle publication.
- API key authentication.
- SDK support for endpoints other than Search Analyze.
- Streaming SDK APIs.
- Reactive SDK APIs.
- Circuit breaker implementation.
- Metrics exporter integration.
- Distributed tracing integration.
- Automatic retry telemetry.
- SDK version compatibility matrix.

## Acceptance criteria

V9 is complete when:

- The Maven reactor builds all modules successfully.
- The server module passes all unit tests.
- The Java SDK module passes all unit tests.
- The examples module compiles successfully.
- The SDK supports sync and async Search Analyze calls.
- The SDK propagates `X-Request-Id`.
- The SDK maps API and transport failures correctly.
- The SDK retries retryable failures with exponential backoff.
- The SDK does not retry non-retryable API failures.
- SDK usage is documented and backed by runnable examples.
- The repository working tree is clean after the release commit.

## Java SDK SSE Streaming

The Java SDK includes an SSE streaming client for the QwenBridge search stream endpoint.

Delivered capabilities:

- Raw SSE event consumption through QwenBridgeStreamingClient
- Typed SSE consumption through streamTyped(...)
- Typed payload mapping for stream.connected, ai.token, ai.completed, and ai.failed
- Unknown-event and malformed-payload fallback handling
- Typed streaming usage example in examples/java-sdk-example
- SDK README documentation for typed streaming usage

Scope boundary:

The SDK streaming surface consumes the existing server SSE contract. Server-side live token forwarding, disconnect cancellation, backpressure, stream limits, and streaming benchmarks remain separate platform work.
